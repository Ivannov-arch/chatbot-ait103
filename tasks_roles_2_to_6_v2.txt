CGC-02 | Entity Extraction & Text Normalization
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Role     : 2 — Entity Extraction
Branch   : feature/CGC-02-preprocessor
New File : chatbot/preprocessor.py
Depends  : None (fully standalone)

Goal
────
Right now the chatbot receives raw user input like "how do i connect to the
internet???". The retriever cannot match "internet" to a database row tagged
"wifi". This file is the translation layer: it cleans the text, removes noise,
and maps synonyms so "internet" becomes "wifi" before any search happens.

Without this, every synonym variation by the user returns nothing.

Context
───────
Called early in Bot.chat() before IntentClassifier and Retriever run.
The output of extract_keywords() feeds directly into Retriever.search().

Function Signatures (do not change — other files depend on these)
──────────────────────────────────────────────────────────────────
  normalize(text: str) -> str
  extract_keywords(text: str) -> list[str]
  expand_synonyms(keywords: list[str]) -> list[str]

Acceptance Criteria
───────────────────
[ ] Create chatbot/preprocessor.py from scratch (no Z_Placeholder exists for this).

[ ] normalize(text: str) -> str
    Must:
      - Lowercase the entire string.
      - Strip leading and trailing whitespace.
      - Remove punctuation characters: ! ? . , ; : ' " ( )
    Must NOT:
      - Remove spaces between words.
      - Alter digits (e.g., "block 2" stays "block 2").
    Test case: normalize("Where is the Canteen???") == "where is the canteen"

[ ] extract_keywords(text: str) -> list[str]
    Must:
      - Tokenize the normalized text into individual words.
      - Remove these English stop words at minimum:
        {"how", "do", "i", "the", "a", "an", "is", "where", "to",
         "for", "in", "can", "my", "what", "when", "who", "does", "are"}
      - Return only non-empty tokens.
    Test case: extract_keywords("how do i connect to the internet")
               == ["connect", "internet"]

[ ] SYNONYM_MAP (dict[str, str] at module level)
    Must contain at minimum these 20 mappings:
      "internet"    -> "wifi"
      "network"     -> "wifi"
      "connection"  -> "wifi"
      "dorm"        -> "hostel"
      "dormitory"   -> "hostel"
      "accommodation" -> "hostel"
      "room"        -> "hostel"
      "grade"       -> "cgpa"
      "pointer"     -> "cgpa"
      "result"      -> "grade"
      "professor"   -> "lecturer"
      "instructor"  -> "lecturer"
      "borrow"      -> "library"
      "book"        -> "library"
      "cafe"        -> "canteen"
      "cafeteria"   -> "canteen"
      "food court"  -> "canteen"
      "mc"          -> "leave"
      "sick"        -> "medical"
      "tuition"     -> "fees"

[ ] expand_synonyms(keywords: list[str]) -> list[str]
    Must:
      - Map each keyword through SYNONYM_MAP if a match exists.
      - Keep the keyword unchanged if not in SYNONYM_MAP.
      - Return a deduplicated list (no duplicate values).
    Test case: expand_synonyms(["connect", "internet"]) == ["connect", "wifi"]

[ ] Add if __name__ == "__main__": block:
    - Prompt the user for input in a loop.
    - Print the normalized text, extracted keywords, and expanded keywords.
    - Exit on "quit".

Test Command (run this to verify your work)
────────────────────────────────────────────
  python -c "
  from chatbot.preprocessor import normalize, extract_keywords, expand_synonyms
  raw = 'how do i connect to the internet???'
  n = normalize(raw)
  kw = extract_keywords(n)
  ex = expand_synonyms(kw)
  print('Normalized :', n)
  print('Keywords   :', kw)
  print('Expanded   :', ex)
  assert 'wifi' in ex, 'FAIL: wifi not in expanded keywords'
  print('PASS')
  "

CGC-03 | Response Matching & Supabase Retrieval
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Role     : 3 — Response Matching & Retrieval
Branch   : feature/CGC-03-retriever
File     : chatbot/retriever.py
Depends  : database/client.py (already implemented — get_client())

Goal
────
Given a module name and a list of expanded keywords, fetch the best matching
Q&A row from the Supabase knowledge_items table. This is the moment the chatbot
becomes useful — if the retriever is wrong, no amount of polish in other parts
will save the answer quality.

Context
───────
Called from Bot.chat() after IntentClassifier returns the module and Preprocessor
returns the expanded keyword list. Returns a list[dict] which Responder then
formats into a readable string.

Reference the Z_Placeholder_retriever.py to understand the database schema:
  - id          UUID
  - module      TEXT
  - question    TEXT
  - answer      TEXT
  - keywords    TEXT[]   <- PostgreSQL array type
  - created_at  TIMESTAMPTZ

Function Signatures (do not change — Bot.chat() depends on these)
──────────────────────────────────────────────────────────────────
  Retriever.__init__(self)
  Retriever.search(module: str, keywords: list[str], top_k: int = 3) -> list[dict]

Acceptance Criteria
───────────────────
[ ] Replace the placeholder in chatbot/retriever.py.

[ ] Retriever.__init__(self)
    - Must call get_client() from database.client and store as self.client.
    - Must NOT make any database queries during init.

[ ] Retriever.search(module, keywords, top_k=3) -> list[dict]
    Strategy (implement in this order — test each step):

    Step 1 — Filter by module:
      Query knowledge_items where module == the given module string.

    Step 2 — Score each row:
      For each row returned, calculate a match_score:
        match_score = number of query keywords found in the row's 'keywords' array
                    + number of query keywords found as substrings in the 'question'
      A keyword is considered a match if it appears as a substring (case-insensitive).

    Step 3 — Filter and sort:
      - Discard rows with match_score == 0.
      - Sort remaining rows by match_score descending.
      - Return only the top_k rows (default: 3).

    Step 4 — Return format:
      Each dict in the returned list must contain at minimum:
        {"question": str, "answer": str, "keywords": list, "score": int}

[ ] Handle edge cases:
    - If the Supabase query raises an exception, catch it, print the error, and return [].
    - If keywords is an empty list, return [] immediately (no DB query needed).
    - If no rows score above 0, return [].

[ ] Add if __name__ == "__main__": block:
    - Hardcode a test: search("academic_navigation", ["library", "borrow"])
    - Print the top result's question and answer.

Test Command (run this to verify your work)
────────────────────────────────────────────

  r = Retriever()
  results = r.search('academic_navigation', ['library'])
  print('Results found:', len(results))
  if results:
      print('Top result:', results[0]['question'])
  else:
      print('No results — check that the database is seeded')
  "

CGC-04 | Multi-Turn Context & Session Management
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Role     : 4 — Context & Session Management
Branch   : feature/CGC-04-context-manager
File     : chatbot/context_manager.py
Depends  : None (standalone in-memory structure)

Goal
────
The chatbot must remember what was said earlier in the same conversation. Without
this, asking "what time does it close?" after "where is the library?" would fail
because the bot has no memory of the previous topic.

This module stores up to MAX_TURNS pairs of (user, bot) messages per session ID.
It deliberately lives in memory — no database needed — for simplicity and speed.

Context
───────
ContextManager is initialized once inside Bot.__init__().
Bot.chat() calls add_turn() after every user message and every bot reply.
Bot.reset() calls clear() to wipe a session.

IMPORTANT: Read Z_Placeholder_context_manager.py first — the skeleton is mostly
correct. Your job is to refine it and make it production-ready.

Function Signatures (do not change — Bot depends on these exact names)
───────────────────────────────────────────────────────────────────────
  ContextManager.__init__(self, max_turns: int = MAX_TURNS)
  ContextManager.add_turn(session_id: str, role: str, message: str) -> None
  ContextManager.get_history(session_id: str) -> list[dict]
  ContextManager.clear(session_id: str) -> None

Acceptance Criteria
───────────────────
[ ] Replace the placeholder in chatbot/context_manager.py.

[ ] Read MAX_TURNS from .env using os.getenv("MAX_TURNS", "5").
    - Convert the result to int. Default to 5 if not set.
    - MAX_TURNS refers to the number of PAIRS (so 5 turns = 10 individual messages).

[ ] ContextManager.__init__(self, max_turns)
    - Store max_turns as self.max_turns.
    - Initialize self._store as an empty dict: {}

[ ] add_turn(session_id, role, message) -> None
    Must:
    - Accept role values: "user" or "bot" only. Raise ValueError for anything else.
    - Append {"role": role, "message": message} to self._store[session_id].
    - After appending, trim self._store[session_id] to the last (max_turns * 2) items.
    - Create the session list automatically if session_id is new.

[ ] get_history(session_id) -> list[dict]
    - Return self._store.get(session_id, []) — never raise an exception.

[ ] clear(session_id) -> None
    - Use dict.pop(session_id, None) — never raise an exception if ID is missing.

[ ] Add if __name__ == "__main__": block:
    Simulate this exact scenario and print results:
      1. Create ContextManager(max_turns=3)
      2. Add 4 user messages and 4 bot replies (8 total messages)
      3. Get history and assert len(history) == 6 (max 3 pairs = 6 messages)
      4. Print "PASS" if assertion succeeds.

Test Command (run this to verify your work)
────────────────────────────────────────────
  python -c "
  from chatbot.context_manager import ContextManager
  ctx = ContextManager(max_turns=2)
  ctx.add_turn('s1', 'user', 'hello')
  ctx.add_turn('s1', 'bot', 'hi there')
  ctx.add_turn('s1', 'user', 'where is canteen')
  ctx.add_turn('s1', 'bot', 'canteen is at block A')
  ctx.add_turn('s1', 'user', 'what time does it open')
  ctx.add_turn('s1', 'bot', 'it opens at 7am')
  h = ctx.get_history('s1')
  assert len(h) == 4, f'Expected 4, got {len(h)}'
  print('History has', len(h), 'messages — PASS')
  "

Goal
────
This ticket produces the finished, talking chatbot. It has three parts:
  1. Responder  — formats raw database rows into a readable reply.
  2. Bot        — the orchestrator that connects every component.
  3. main.py    — the terminal REPL where a user can actually have a conversation.

This is the role where everything comes together. Test early and often.

PART A — chatbot/responder.py
─────────────────────────────
Read Z_Placeholder_responder.py first.

Acceptance Criteria
───────────────────
[ ] Implement Responder.format(results: list[dict], query: str) -> str
    - If results is empty, return the FALLBACK_MESSAGE.
    - If results has 1 item, return its "answer" directly.
    - If results has 2+ items, return the top result's "answer" only (the best match).
      Optionally append: "\n\nRelated: <second result question>" as a hint.

[ ] Improve FALLBACK_MESSAGE — it must be module-aware.
    - Change the function signature to: format(results, query, module="unknown") -> str
    - If module is "admin_directory":
        fallback = "I couldn't find that info. Try contacting ISAO at isao@xmu.edu.my."
    - If module is "campus_life":
        fallback = "I couldn't find that info. Try the Student Affairs Office at student.affairs@xmu.edu.my."
    - If module is "academic_navigation":
        fallback = "I couldn't find that. Contact your academic advisor or the Registrar's Office."
    - If module is "unknown":
        fallback = "I'm not sure what you're asking. Try asking about campus facilities, academic matters, or administrative services."

PART B — chatbot/bot.py
────────────────────────
Read Z_Placeholder_bot.py first.

Acceptance Criteria
───────────────────
[ ] Implement Bot.__init__(self):
    - Import and instantiate: IntentClassifier, Retriever, ContextManager, Responder.
    - Store each as: self.intent, self.retriever, self.context, self.responder.

[ ] Implement Bot.chat(session_id: str, message: str) -> str:
    Execute this pipeline in order:
      Step 1: Log user message:
        self.context.add_turn(session_id, "user", message)
      Step 2: Classify intent:
        module = self.intent.classify(message)
      Step 3: Preprocess message:
        from chatbot.preprocessor import normalize, extract_keywords, expand_synonyms
        keywords = expand_synonyms(extract_keywords(normalize(message)))
      Step 4: Retrieve candidates:
        If module == "unknown" OR keywords is empty:
          results = []
        Else:
          results = self.retriever.search(module, keywords)
      Step 5: Format reply:
        reply = self.responder.format(results, message, module)
      Step 6: Log bot reply:
        self.context.add_turn(session_id, "bot", reply)
      Step 7: Return reply.

[ ] Implement Bot.reset(session_id: str) -> None:
    - Call self.context.clear(session_id).

CGC-06 | Dataset Audit, Validation & Keyword Normalization
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Role     : 6 — NLP & Text Preprocessing Lead
Branch   : feature/CGC-06-dataset-audit
Files    : database/seeds/*.json, scripts/validate_seeds.py (new)
Depends  : None (can be worked on in parallel with all other tickets)

Goal
────
The chatbot is only as good as its data. Garbage in = garbage out.
This ticket ensures the 357 seeded rows are factually correct, structurally
consistent, and keyword-compatible with the synonym map in CGC-02.

If a keyword in the JSON seed is "Internet" (capital I) and the SYNONYM_MAP
maps "internet" (lowercase), the retriever will never score that row.
This audit catches and fixes problems like that before integration testing.

Acceptance Criteria
───────────────────
[ ] Write scripts/validate_seeds.py (new file).
    This script, when run, must:

    Check 1 — Structural Integrity:
      - Load each of the 3 JSON files.
      - Assert every row has non-empty "module", "question", "answer", "keywords".
      - Print a PASS/FAIL report per file.

    Check 2 — Keyword Normalization:
      - Assert every keyword in every row is fully lowercase (no capital letters).
      - Print which rows have uppercase keywords and which file they belong to.

    Check 3 — No cross-module keyword conflicts:
      - Build a flat dictionary of keyword -> [modules it appears in].
      - Flag any keyword that appears in 2 or more different modules.
      - Print a warning for each conflict found (this helps tune IntentClassifier).

    Check 4 — Synonym compatibility (run AFTER CGC-02 is done):
      - Import SYNONYM_MAP from chatbot.preprocessor.
      - Check that no keyword in the seeds is a synonym key that should already
        be normalized (e.g., "internet" should not be a keyword; "wifi" should be).
      - Print warnings for every incompatible keyword found.

[ ] Fix any issues found by the validation script directly in the JSON files.

[ ] Final seed re-upload:
    - After fixing, truncate the knowledge_items table in Supabase SQL Editor:
        TRUNCATE TABLE knowledge_items;
    - Re-run: python -m database.seed
    - Confirm the row count matches the local JSON count.

Test Command (run the audit)
─────────────────────────────
  python scripts/validate_seeds.py
